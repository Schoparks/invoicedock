# 票栈 · InvoiceDock

面向个人与小团队的发票归集和报销管理工具。把导入、收票、人工核对、金额匹配和报销记录放在同一个工作台，支持本地运行。

基于 Python、FastAPI、SQLite 和原生 JavaScript，无需前端构建。PDF 提取和图片 OCR 在运行服务的机器上完成，不依赖外部模型或付费识别 API。

## 功能

- **多格式导入**：支持 PDF、PNG、JPG、WEBP、XML、OFD 和 ZIP，提取号码、金额、日期、购销方及类别，核对后用于报销。
- **统一票库**：个人与已分享的群组发票统一展示，标明归属和上传者，可筛选个人或特定群组；多群组分享的同一张发票只展示一次；统一台账导出附带当前可见的群组及发票所有者。
- **自动收票**：绑定公网 IMAP 邮箱，或通过自有域名与签名邮件入口接收附件；支持收票记录和失败重试。
- **金额匹配**：按个人、本人全部发票或特定群组，以及类别、项目、日期及购买方筛选，支持“稍多”和“稍少”：稍多优先恰好达到、否则超出最少；稍少优先恰好达到、否则选择低于目标且最接近的组合。
- **报销与额度**：管理草稿、提交、报销、取消及驳回状态，保留历史快照，避免一票重复报销。
- **预览与下载**：在当前页预览 PDF（可翻页）、图片和 XML，单独下载原件；报销单内可批量下载原件、选择重命名并逐张编辑文件名。OFD 提供下载。
- **导出与备份**：导出票库 Excel、报销附件 ZIP，或下载个人数据备份。

## 快速开始

需要 Conda 和 Python 3.12。

```sh
git clone https://github.com/Schoparks/invoicedock.git
cd invoicedock
conda env create -f environment.yml
conda activate invoice-desk
python run.py
```

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)，注册账号后登录。不创建 `.env` 时按本地默认配置运行，数据保存在 `data/`。按 Ctrl+C 停止，可用 `python run.py --port 8766` 更换端口。

macOS 安装好环境后，也可双击 `启动票栈.command`。项目沿用 `invoice-desk` 环境名和 `INVOICE_*` 配置名，以兼容现有配置。

已有环境更新依赖：

```sh
conda activate invoice-desk
python -m pip install -r requirements.lock.txt
```

`environment.yml` 使用跨平台的 Conda 环境定义与锁定的 Python 依赖；`conda-osx-arm64.lock.txt` 仅适用于 Apple Silicon 的 Conda 基础包复现。

## 使用流程

1. **导入并核对**：导入或手动录入时选择个人或群组归属；选择群组会分享给该组，所有权仍归本人。票库统一展示全部可见发票，可按归属筛选。上传文件后，在票库操作列可直接预览或进入核对。核对卡片上方直接展示原件，下方填写票面字段，底栏固定；点击“确认核对”同时保存字段并标记已核对，无需额外勾选。销售方、开票日期和大于零的金额填写完整后才可确认；已占用或无编辑权限的发票保持只读。同账号按原件内容和发票号码去重；同票多格式归为一条，有 PDF 时只保留 PDF 原件。XML/OFD 可补全未核对记录的空字段，随后丢弃，已核对内容不被覆盖。
2. **整理项目与额度**：个人与群组的项目、额度统一展示，按归属筛选；新建时选择归属。按项目归类，按报销月份和类别设定额度。只有关联该额度的报销单计入使用，开票日期与报销月份分别管理。
3. **匹配金额**：筛选可用发票，输入目标金额。默认“稍多”，优先恰好达到目标，否则选择超出最少的组合；票额不足时提示额度不足。选择“稍少”时，优先恰好达到目标，否则选择低于目标且最接近的组合。金额最优优先；同等合计先尽量减少他人的群组票金额，再减少本人群组票金额，优先使用个人发票。关联群组额度时仅匹配该组已分享发票，关联个人额度可使用全部可见来源。关联月度额度时，两种方式均不超过剩余额度；稍少可在目标高于剩余额度时继续匹配。匹配页使用紧凑标题并省去装饰性页脚，桌面双栏占满剩余视口，条件与结果独立滚动，窄屏上下排列。其他组是替代建议，不保证全局第二、第三名或票数最少。每次最多 1,000 张候选，目标最高 100,000 元。
4. **创建报销单**：从匹配结果或手动多选创建草稿，选择报销归属，再提交、标记已报销。个人报销单可组合不同可见来源，仅创建者可访问；群组报销单只可使用已分享到该组的发票，向该组成员开放。项目和额度须与报销单归属一致。草稿、已提交和已报销占用发票及额度；取消或驳回释放占用并保留快照。同一发票分享到多个组后仍只有一份全局使用状态。
5. **预览与导出**：发票详情与报销明细提供页内预览、原件下载；PDF 按页显示，图片直接显示，XML 以纯文本显示，OFD 须下载查看。报销单内可仅批量下载原件 ZIP，或导出含历史明细、JSON 与原件的完整报销包。默认保留原文件名；勾选“下载时重命名原件”后，建议文件名为 `001-餐饮-128.50.pdf`（序号-类别-金额），可逐张编辑，扩展名保持不变。命名取报销历史快照，仅影响下载文件；重名文件自动加后缀，无原件记录在 ZIP 中单独说明。撤销分享后的历史原件仍可由该报销单有权访问者查看、下载。

## 账号设置

仅支持邮箱和密码登录。用户名用于显示，支持中文、允许重名，长度为 1 至 80 个字符；原有姓名／昵称直接沿用，无需重新注册。

在“账号设置”中可修改用户名、登录邮箱及密码，保存时须验证当前密码。邮箱不可与其他账号重复；密码为 10 至 128 个字符。修改邮箱或密码后，当前设备保持登录，其他设备的登录会失效；修改邮箱后请使用新邮箱登录。

修改账号资料不会改变账号编号、发票归属、群组关系、自有域名收票地址或已绑定的 IMAP 邮箱。当前未提供邮箱验证码验证或忘记密码自助找回。

## 共享与权限

个人发票默认仅所有者可见。每个账号都可创建多个组，群主或管理员可生成有效期 7 天、仅能使用一次的邀请码，供已注册账号加入。

| 操作 | 权限 |
| --- | --- |
| 编辑、删除、设置个人发票分享 | 发票所有者；有报销历史的发票不能删除 |
| 查看组内共享发票、下载原件、创建组报销单和组项目 | 该组成员 |
| 变更组报销单状态 | 报销单创建者、群主或管理员 |
| 管理组额度、邀请码 | 群主或管理员 |
| 创建归入群组的收票邮箱或地址 | 该组成员；发票归创建者并分享至该组 |
| 查看、编辑、删除邮箱配置及查看收票记录、重试 | 仅配置创建者，群主和管理员也不能访问他人的邮箱 |
| 修改团队名称及说明 | 群主或管理员 |
| 设置或撤销管理员、转让群主、解散团队 | 群主 |
| 移除成员 | 群主可移除其他成员；管理员只能移除普通成员 |
| 退出团队 | 成员或管理员；群主须先转让，或解散团队 |

在“群组管理 → 团队设置”中修改名称（1 至 100 字符）及说明（最多 1,000 字符），查看成员并按角色管理。群主可将团队转让给现有成员，转让后自己成为管理员；解散须输入团队名称确认。管理员不能修改他人的票面信息。

退出或移除成员时，其发票停止在本团队共享；涉及其发票、或由其创建的草稿及已提交报销单会整单取消，释放发票占用和额度。其他团队的分享及报销不受影响。单独撤销分享仍须先处理对应的未完成报销。

解散团队时，全部未完成报销单取消，全部团队分享和邀请码失效，团队项目、额度及发票上的相关项目归类清除。历史报销单与票面快照保留在报销单创建人的个人空间，仅该创建人可访问该历史报销单和包内原件；发票本身的所有权及原件始终由原上传者保留。**已报销发票保留已报销状态，不能因退出或解散而再次报销。**

离队成员创建的团队邮箱及域名收票地址会转回其个人空间并暂停；解散时对全组收票配置执行同样处理。凭据、收票记录与已接收队列保留，已经接收或正在处理的附件仍归原账号入库；后续新邮件须由原账号在个人空间重新启用收票后接收。

## 邮箱收票

### 绑定已有邮箱

“邮箱收票”统一展示本人创建的个人及群组收票配置，按卡片标明发票归属，可按归属筛选。创建时选择归属，编辑可修改名称、配置和归属，删除不会删除已导入发票。群组邮箱配置及收票记录仅创建者可见。

在“邮箱收票”填写 IMAP 主机、账号和服务商提供的应用专用密码或授权码。仅支持验证证书的公网 TLS 993 端口，默认文件夹为 `INBOX`。

- 首次绑定从当前时点开始处理新邮件，不自动回读历史邮件。
- 只读获取附件，不删除邮件、不改变未读标记，不抓取正文下载链接。
- 默认每轮结束后等待 60 秒，也可手动收取；每轮最多 50 封，每封完整邮件最多 20 MB、最多 200 个发票文件。
- 失败附件可重试，成功附件不会重复入库。组邮箱的发票归绑定人，并自动分享到对应组。
- 授权码加密保存，不会回填到页面；不支持邮箱 OAuth。
- 收票记录中的“查看原件”可查看原始邮件正文、内嵌二维码图片及附件信息，并下载 `.eml`。IMAP 原邮件从原收件箱只读获取；已删除、UID 重置或不可读取的邮件会提示不可用。

### 自有域名收票

配置 `INVOICE_RECEIPT_DOMAIN` 和服务端入站密钥后，可创建个人或自己所在群组的收票地址。名称和归属可编辑，邮箱地址保持不变；归属修改仅影响后续接收的邮件，已接收队列使用接收时冻结的归属。删除后停止收新邮件并从列表隐藏，地址永久保留原归属、不能被重新注册，避免历史发票误投；已接收邮件仍按原归属完成处理。可信邮件上游使用 SMTP 信封收件地址签名，将原始邮件投递到服务端，持久保存后再后台识别。

收票记录提供“查看原件”，查看原始邮件正文、内嵌图片和附件信息，并下载 `.eml`；仅地址创建者可访问。域名邮件及收票记录按接收时间保留 30 天，成功、忽略、失败及待处理邮件均到期一起清理，连同附件处理结果删除；已经入库的发票及发票原件继续保留。超过 30 天的记录不再展示、查看或重试；原文缺失的旧记录同样按此期限清理。旧版已清理的原邮件无法补回；无原文的记录直接显示“原邮件已清理”，不显示查看按钮。预览只显示文字与内嵌图片，外部图片须手动打开，不执行邮件 HTML 或自动访问正文链接。

应用只接收可信上游的签名邮件，不依赖具体云服务。可选的 Cloudflare Email Worker 独立部署，先将邮件暂存到私有 R2，再由 Cron 投递至既有入口；网络失败由 Worker 自动退避重试，收到持久化确认后清理暂存；7 天未送达则清理原文并邮件通知已验证的管理员，提醒失败保留小任务重试。服务器无需 R2 凭据、拉取线程或云端地址同步。原通用投递脚本仍可用于自建邮件上游。配置和边界见 [部署说明](DEPLOY.md#自有域名收票)。

## 配置与数据

本地直接启动无需 `.env`。生产部署从 `.env.example` 配置自己的域名、路径和注册策略；示例启用了 HTTPS Secure Cookie，不应原样用于普通 HTTP 本地登录。

| 配置 | 用途 |
| --- | --- |
| `INVOICE_DATA_DIR` | 数据目录，默认项目下 `data/` |
| `PORT` | 回环监听端口，默认 8765 |
| `ALLOW_REGISTRATION` | 是否开放注册，本地默认开放，生产示例关闭 |
| `COOKIE_SECURE` | HTTPS 部署设为 `true` |
| `INVOICE_ALLOWED_HOSTS` | 允许访问的主机名 |
| `INVOICE_MAIL_WORKER` | 是否开启后台 IMAP 收票 |
| `INVOICE_RECEIPT_DOMAIN` | 自有域名收票使用的域名 |

完整配置见 [DEPLOY.md](DEPLOY.md)。服务仅监听回环地址，公网访问通过 HTTPS 反向代理提供；运行时保持单进程。

数据目录包含 SQLite 数据库、`originals/` 原件及邮箱加密密钥 `secret.key`。服务器部署建议将数据放在源码目录外。账号、群组、共享关系及报销历史也在数据库中，升级时会执行必要的表结构迁移。

页面“个人数据备份”不包含全站数据库、其他账号、组报销单或邮箱密码，当前也没有 JSON 自动恢复入口。整站恢复须保存同一时间点的完整数据、原密钥和配置，详见 [备份、恢复与升级](DEPLOY.md#备份恢复与升级)。

## 更新

更新脚本沿用“一次命令拉取代码、按需安装依赖”的方式：

```sh
./update.sh
```

Windows 可运行 `./update.ps1` 或双击 `update.cmd`。脚本使用 Conda 的 `invoice-desk` 环境；若 Conda 不在 PATH，可用 `INVOICEDOCK_PYTHON` 指定该环境内 Python 的绝对路径。也可激活环境后执行 `python update.py`。

脚本要求 `main` 分支和干净工作区，通过 `git pull --ff-only origin main` 更新；仅在锁文件变化、已安装依赖缺失或版本不符时安装依赖。遇到本地改动或分叉会停止，不覆盖配置、数据或强制重置 Git。

运行更新脚本前，请保存工作并备份重要数据。

## 开发

```sh
conda run -n invoice-desk python -m unittest discover -s tests -v
node --check static/app.js
node --test tests/test_email_worker.mjs
```

Node.js 仅用于开发检查，运行应用不需要。测试使用临时数据库、合成票据及模拟邮件服务，覆盖解析、匹配、权限、占用、导出、迁移、去重和收票重试；自动化检查不能替代实际部署验收。

```text
app/           业务接口、权限、数据迁移、解析与收票
static/        无构建步骤的前端
tests/        自动化检查
deploy/       通用部署模板与邮件上游
run.py        单进程服务入口
manage.py     创建账号与重置密码
update.py     Git 拉取及按需更新依赖（含 Shell/Windows 入口）
```

参与维护前请阅读 [AGENTS.md](AGENTS.md)，按变更更新文档与必要检查。报告问题请说明复现步骤和运行环境，不要上传真实发票、邮件原文、数据库或凭据。

## 当前边界

- 自动识别不负责发票验真、税务判断或报销制度审核；票面质量和格式差异可能影响提取，须人工核对。
- 单个导入文件最多 20 MB，一次最多 200 个文件、展开后合计 100 MB，PDF 最多 50 页。
- OFD 仅读取其中可提取的 XML 文字，不转换为 PDF，不保证支持所有厂商格式。
- 同一票库不支持多进程或多副本并行运行。
- 忘记密码由服务器维护者通过 `manage.py reset-password` 处理；没有邮件找回流程或可浏览全站数据的应用管理员。
- 未接入微信自动收票、发票查验或自动行程聚类。
